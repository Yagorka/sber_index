# Что выполнено по критерию новостей

Используются решения ЦБ и небольшой реестр региональных событий. Есть прогнозная
абляция против базы и плацебо: `artifacts/news_ablation/`. Отрицательный результат
не является нарушением критерия: полезность признаков не обязана оказаться положительной.
Недельные расходы маркетплейсов являются внешним временным рядом, а не новостями.

Схема согласования:

1. Хранить дату события отдельно от `published_at`; при сборе корпуса также хранить `first_seen_at`.
2. Доступность сообщения: `max(published_at, first_seen_at)`; если `first_seen_at` неизвестна,
   использовать проверенную дату публикации и явно отмечать отсутствие истории сбора.
3. Привязывать событие к устойчивому `territory_id` через регион и территорию, действовавшую
   на дату события. Неоднозначное сопоставление оставлять неразрешённым. Текущий код
   использует название внутри региона; полноценный исторический справочник соответствий не реализован.
4. Для месячного прогноза включать только сообщения, доступные к дате выдачи; учитывать
   сообщения в окнах прошлых месяцев. `NewsFeatures` теперь не датирует признаки раньше
   максимума дат события и публикации. У исходного реестра не все даты проверены независимо.
5. Для детекторов отдельно сравнить финансовый остаток без новостей и модель с доступными
   событийными признаками при одинаковом бюджете тревог. Только затем оценивать вклад
   новостей в обнаружение; использовать новости для разметки и для признаков одновременно
   без независимой проверки нельзя.

**Пункт 5 реализован в региональном пилоте.** Сравнены прогнозы и входы CUSUM, PageHinkley, BOCPD без новостей, с новостями, с контролем покрытия и с задержанными признаками. Пороги калибруются при одном бюджете; финансовые proxy-метки не используют новости. Устойчивый выигрыш не доказан. [Результаты](REGIONAL_NEWS_IMPACT_RU.md).

Предоставленная формулировка не требует embeddings, LLM или большого текстового
корпуса. Однако для более убедительного выполнения нужны больше независимо
проверенных сообщений и явно показанная интеграция в обе задачи.
