# Источники и объём новостей для следующего эксперимента

Собирать отдельную ленту каждого МО не требуется. Одна общая лента подходит,
если сообщения о локальных событиях извлекаются и получают регион/territory_id.
Новостной источник и география описанного события — разные поля.

| Источник | Задача | Замечание |
|---|---|---|
| Банк России: https://cbr.ru/development/RSS/ | Общая политика, ставка, официальные сообщения | Не ограничиваться числом ставки; исторические публикации брать из архива |
| Интерфакс: https://www.interfax.ru/rss.asp | Общая лента, в том числе сообщения о регионах | RSS для нового сбора; наличие полного исторического архива нужно проверять отдельно |
| Региональные МЧС, пример https://56.mchs.gov.ru/deyatelnost/press-centr/novosti | Паводки, аварии, эвакуации, предупреждения | Есть RSS и фильтр дат; служебные и поздравительные новости отфильтровывать |
| [Оренбург Медиа](https://orenburg.media/) | Экономика, общество, транспорт, торговля, происшествия | JSON WordPress: index.php?rest_route=/wp/v2/posts; архив 2023–2024 реально скачан, 24/24 месяца; заголовки, date_gmt, кеш; история редактирования неизвестна |
| GDELT: https://gdeltproject.org/data.html | Архивные метаданные и поиск ссылок | DOC API описывает окно последних 3 месяцев; для 2023–2024 нужны архивы. Полные GKG архивы велики |

Для лёгкого пилота: общероссийские события и 3–5 регионов, представленных в
муниципальной панели, заранее выбранных по покрытию и доступности источника.
Выбор регионов нельзя делать по успешным тревогам детектора. Выводы пилота не
переносятся на все территории.

Минимум полей: URL, источник, заголовок, дата публикации, отдельно дата события,
география, категория события и дата скачивания (`fetched_at`). Дата скачивания
архива не равна исторической дате публикации. При неизвестных исторических
винтажах использование даты публикации остаётся явно указанным допущением.
Для будущего онлайн-сервиса доступность учитывает также момент первого
получения сообщения системой.

Начать с тематических событий и простых счётчиков за прошлые окна; перепечатки
одного события объединять. Сравнить «без новостей», «общие», «общие + региональные»
для прогноза и для детектора при одинаковом бюджете тревог. Оценивать только
непросмотренные факты; результаты на текущем тесте будут исследовательскими.

Режим сбора для слабой нагрузки: HTTP/RSS, один worker, кеш ответов и пауза между
запросами. Массовый запуск браузеров, LLM на каждую статью и полный GDELT-архив
для первого пилота не нужны.
